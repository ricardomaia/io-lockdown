# I/O Lockdown

[![Deploy GitHub Pages](https://github.com/ricardomaia/io-lockdown/actions/workflows/pages.yml/badge.svg)](https://github.com/ricardomaia/io-lockdown/actions/workflows/pages.yml) [![Build and Test](https://github.com/ricardomaia/io-lockdown/actions/workflows/build.yml/badge.svg)](https://github.com/ricardomaia/io-lockdown/actions/workflows/build.yml) [![Release](https://github.com/ricardomaia/io-lockdown/actions/workflows/release.yml/badge.svg)](https://github.com/ricardomaia/io-lockdown/actions/workflows/release.yml)

I/O Lockdown is a Windows endpoint security tool designed to protect workstations from physical peripheral attacks and data exfiltration while the system is locked or unattended.

## Download

The latest installer is available on the [GitHub Releases](https://github.com/ricardomaia/io-lockdown/releases/latest) page.

Download `IOLockdown_Installer.msi` and run it with administrator privileges. The installer registers the background service and places the tray icon in the startup programs.

## Defense Objectives & Strategy

The software implements a **Fail-Close** policy to mitigate attack vectors such as BadUSB (Rubber Ducky), hardware Keyloggers, and Rogue Network Adapters.

### 1. Logical Blocking (Locked Session)
Upon detecting a session lock (`Win+L`), the system executes:
- **Network Kill-Switch:** Disables all network adapters (Ethernet/Wi-Fi) via WMI.
- **USB Storage Block:** Disables the `USBSTOR` service in the registry to prevent mounting unauthorized drives.
- **Real-time Whitelisting:** Captures the current state of trusted hardware entities.

### 2. Anti-Tampering Monitoring (Hardware)
While active, the application monitors the PnP (Plug and Play) bus. If any physical change occurs (connection of a new device or removal of an existing one):
- **Violation Detection:** Instantly identifies changes via `WM_DEVICECHANGE` events and WMI watchers.
- **Visual Evidence:** Automatically captures a photo of the intruder using the available webcam.
- **Total Lockdown:** Disables all USB controllers (Hubs and Root Controllers) via PowerShell (`Disable-PnpDevice`).
- **Security Persistence:** The "Violation Detected" state prevents automatic re-activation of interfaces upon unlocking — requires a manual reset via the audit console.

### 3. Smart Lock (Bluetooth Proximity)
The system can monitor a paired Bluetooth device (e.g., your smartphone). If the device goes out of range for three consecutive checks, Windows is automatically locked.

## Operation Modes
- **Audit Interface:** A system tray application for real-time log monitoring.
- **Service Mode:** Runs as a Windows Service (`IOLockdownService`) for system-level protection, started automatically on boot without requiring user login.

## Build Instructions

### Prerequisites
- **.NET 9.0 SDK**
- **WiX Toolset v5** (for MSI generation)
- **Administrator Privileges** (for hardware manipulation)

### Compilation Steps
1. **Clone the repository:**
   ```bash
   git clone https://github.com/ricardomaia/io-lockdown.git
   cd io-lockdown
   ```
2. **Run tests:**
   ```powershell
   dotnet test io-lockdown.Tests/io-lockdown.Tests.csproj -c Release
   ```
3. **Build the executable:**
   ```powershell
   ./build.ps1
   ```
4. **Generate the MSI installer:**
   ```powershell
   ./make-msi.ps1
   ```

## Release Process

Releases are published automatically via GitHub Actions:

1. Create a branch from `main` named `release/vX.Y.Z`.
2. Open a Pull Request targeting that branch — the **Build and Test** workflow runs tests and builds the MSI as a validation artifact.
3. Merge the PR — the **Release** workflow triggers automatically, builds the MSI, creates a Git tag `vX.Y.Z` (version read from `io-lockdown.csproj`), and publishes a GitHub Release with the MSI attached.

To publish manually (e.g., for hotfixes):
```powershell
./make-msi.ps1
gh release create vX.Y.Z IOLockdown_Installer.msi --title "I/O Lockdown vX.Y.Z" --generate-notes
```

## Windows 11 VirtualBox Test VM

This repository can be tested in an isolated Windows 11 VM using the local ISO at:

```text
ISO\Win11_25H2_EnglishInternational_x64_v2.iso
```

> **Warning:** Never run the compiled binary or installer on the host machine. Always test inside the VM — the application disables network adapters and USB ports, which would interrupt host connectivity immediately.

### Host Prerequisites
- **Oracle VirtualBox 7.2+**
- Hardware virtualization enabled in BIOS/UEFI
- At least **8 GB free RAM** and **80 GB free disk space** for the VM
- The installer generated by `./make-msi.ps1`

### VM Configuration
The local test VM is named `io-lockdown-win11-test` and was configured with:

- **OS:** Windows 11 Pro, English International, x64
- **CPU:** 4 vCPUs
- **Memory:** 8192 MB
- **Disk:** 80 GB VDI
- **Firmware:** EFI
- **TPM:** 2.0
- **Network:** NAT
- **USB:** xHCI enabled
- **Guest Additions:** installed by the unattended installer

Default local test credentials:

```text
User: iolab
Password: ChangeMe!2026
```

### VirtualBox Commands
Create and prepare the VM from PowerShell:

```powershell
$VBoxManage = "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe"
$Iso = "$PWD\ISO\Win11_25H2_EnglishInternational_x64_v2.iso"
$VmName = "io-lockdown-win11-test"

& $VBoxManage createvm --name $VmName --ostype Windows11_64 --register
& $VBoxManage modifyvm $VmName --memory 8192 --cpus 4 --vram 128 --graphicscontroller vboxsvga --firmware efi --ioapic on --chipset ich9 --pae on --rtcuseutc on --boot1 dvd --boot2 disk --nic1 nat --usb on --usbxhci on --clipboard bidirectional --draganddrop bidirectional --audio-driver none
& $VBoxManage modifyvm $VmName --tpm-type 2.0
& $VBoxManage storagectl $VmName --name SATA --add sata --controller IntelAhci --portcount 2 --bootable on
& $VBoxManage createmedium disk --filename "$env:USERPROFILE\.VirtualBox\VMs\$VmName\$VmName.vdi" --size 81920 --format VDI
& $VBoxManage storageattach $VmName --storagectl SATA --port 0 --device 0 --type hdd --medium "$env:USERPROFILE\.VirtualBox\VMs\$VmName\$VmName.vdi"
& $VBoxManage storageattach $VmName --storagectl SATA --port 1 --device 0 --type dvddrive --medium $Iso
& $VBoxManage unattended install $VmName --iso=$Iso --user=iolab --password="ChangeMe!2026" --full-user-name="IOLockdown Lab" --hostname=io-lockdown-win11-test.local --locale=en_GB --country=GB --time-zone=America/Sao_Paulo --image-index=6 --install-additions --start-vm=none
```

Start the VM:

```powershell
& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" startvm io-lockdown-win11-test --type gui
```

For headless installation or CI-like validation:

```powershell
& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" startvm io-lockdown-win11-test --type headless
& "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe" controlvm io-lockdown-win11-test screenshotpng .\vm-install-status.png
```

### Test Flow
1. Build the MSI on the host:
   ```powershell
   ./make-msi.ps1
   ```
2. Start the VM and sign in with the local test account.
3. Copy and install the MSI in the VM:
   ```powershell
   ./run-in-vm.ps1
   ```
4. To copy and start the published executable directly instead of the MSI:
   ```powershell
   ./run-in-vm.ps1 -ArtifactPath .\publish\io-lockdown.exe -Mode RunExe
   ```
5. Validate lock/unlock behavior, USB storage blocking, network adapter restoration, and violation handling inside the VM before testing on physical hardware.

`run-in-vm.ps1` uses `VBoxManage guestcontrol`, so the Windows guest must be fully installed, running, signed in as `iolab`, and have VirtualBox Guest Additions active. The application manifest requests administrator privileges; when starting the EXE directly, approve the UAC prompt in the VM GUI if Windows shows one.

## System Requirements
- **OS:** Windows 10/11
- **Privileges:** Run as Administrator.

## Technologies
- **C# / .NET 9.0:** Core logic and UI.
- **WMI & PnP PowerShell:** Low-level hardware state management.
- **Win32 API:** Real-time hardware events and session control.
- **InTheHand.Net:** Bluetooth integration for Smart Lock.
- **UWP MediaCapture:** Violation evidence photography.

*Warning: Accidental disconnection of a trusted device while the screen is unlocked will lock the workstation and disable network access. The "Violation Detected" state requires a manual reset via the audit console before network and USB storage are restored.*
